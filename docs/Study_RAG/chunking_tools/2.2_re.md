## 1. Why regular expressions help

A Markdown file contains structure that is visible in the text: headings (`#`, `##`), blank lines, and code fences. We want the *character positions* of meaningful boundaries, not just the matching words.

`re` searches for patterns and returns match objects with the exact start/end offsets into the original string.

## 2. Your first regex

```python
import re

text = 'A port is 8000. Another port is 9000.'
for match in re.finditer(r'\d+', text):
    print(match.group())
```

Output:

```text
8000
9000
```

`r'...'` is a raw Python string. `\d` matches a digit and `+` means one or more. Use raw strings for regexes to avoid accidental Python string escapes.

## 3. `finditer()` and character offsets

```python
import re
text = '# Intro\nHello.\n## Port\nUse 8000.\n'
for match in re.finditer(r'^#{1,6}[ \t]+.+$', text, re.MULTILINE):
    print(repr(match.group()), match.start(), match.end())
    assert text[match.start():match.end()] == match.group()
```

`start()` is inclusive; `end()` is exclusive. These are **character offsets** in `text`, exactly what your `MinimalSource` needs. Unlike splitting and rejoining the document, regex matching leaves the original offsets unchanged.

## 4. Reading a heading pattern

```text
^             beginning of a line (with re.MULTILINE)
#{1,6}        one to six # characters
[ \t]+        at least one space or tab
.+            heading content
$             end of that line
```

This matches basic ATX headings such as `## Installation`. It does **not** fully implement the CommonMark heading specification (for example, headings can have optional indentation and closing `#` markers). Decide how much Markdown syntax your corpus needs and document that decision.

## 5. `re.MULTILINE` versus `re.DOTALL`

- `re.MULTILINE`: `^` and `$` also match line boundaries inside a string.
- `re.DOTALL`: `.` can match a newline.

They solve different problems; don't enable `DOTALL` just because the file has multiple lines.

## 6. The fenced-code trap

```markdown
# Guide

```bash
# this is a shell comment, NOT a Markdown heading
vllm serve model
```

## Configuration
```

A regex run across the entire document may mistake the shell comment for a heading. A practical first strategy:

1. Walk through the original lines with `splitlines(keepends=True)`.
2. Track whether you are inside a fenced code block.
3. Only look for headings when you are *outside* a fence.
4. Track the running original character offset.

**Important:** Real Markdown fences can use backticks or tildes and have varying lengths. A single `inside_fence = not inside_fence` at every line containing three backticks is only a teaching shortcut, not a fully correct parser. Also consider indented code and headings inside HTML for a more complete implementation.

## 7. Paragraph boundaries and oversized sections

An initial chunking strategy can group lines between headings, then fall back to blank-line boundaries if a section is too large; if still too large, fall back to line boundaries and finally fixed-width slicing.

For arbitrary strings, a simple paragraph separator pattern is `r'\n[ \t]*\n'`, but beware: Windows CRLF, multiple blank lines, code fences, and lists require more care.

When a section exceeds `max_chunk_size`, **splitting does not require replacing text**. Keep integer `(first, last)` intervals into the original file. Optional overlap must also preserve that constraint.

## 8. Connecting matches to chunks

Suppose the document has heading starts at character indices `[0, 120, 390]` and length 600. Candidate ranges are:

```python
starts = [0, 120, 390]
ends = starts[1:] + [600]
ranges = list(zip(starts, ends))
# [(0, 120), (120, 390), (390, 600)]
```

Then validate each `0 <= first < last <= len(text)` and `last - first <= max_chunk_size`. Each chunk's `text` should equal `file_text[first:last]` exactly. Indexing context such as heading ancestry belongs in `index_text`, not in the source offsets.

## 9. Common mistakes

- Calling `re.findall()` when you need offset positions: prefer `finditer()`.
- Treating any line beginning with `#` as a heading (including code fences and shell comments).
- Removing whitespace with `.strip()` before computing ranges, which shifts offsets.
- Assuming regexes implement all Markdown syntax.
- Using `.` without understanding how newlines are treated.
