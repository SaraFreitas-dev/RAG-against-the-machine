## 1. AST versus tokens

`ast` represents syntactic structure: functions, classes, imports and expressions. `tokenize` exposes lower-level pieces such as names, operators, indentation, newline types, strings and **comments**. The two tools answer different questions.

For example, `ast` finds the definition of `def add(...)`, but it does not preserve nearby comments as dedicated comment nodes. `tokenize` can find those comments.

## 2. Inspecting tokens

```python
import tokenize
from io import StringIO

code = '# API helper\ndef hello():\n    return 42\n'
for tok in tokenize.generate_tokens(StringIO(code).readline):
    print(tokenize.tok_name[tok.type], repr(tok.string), tok.start, tok.end)
```

A token exposes its type, string content, `(line, column)` start and `(line, column)` end. Not all tokens represent visible text (for example, `INDENT`, `DEDENT` and `ENDMARKER`).

## 3. Finding comments

```python
import tokenize
from io import StringIO

code = '# explanation\ndef hello():\n    return 42  # answer\n'
for tok in tokenize.generate_tokens(StringIO(code).readline):
    if tok.type == tokenize.COMMENT:
        print(tok.string, tok.start)
```

Possible output:

```text
# explanation (1, 0)
# answer (3, 15)
```

This lets you decide whether leading comments belong with a function, while avoiding a false match on `#` inside a string literal.

## 4. Token positions versus character offsets

**Important nuance:** Python tokenizer columns are not automatically global character offsets. `generate_tokens()` reports `(line_number, column)` coordinates for **decoded strings**. The Python AST's `col_offset` and `end_col_offset` instead refer to UTF-8 byte offsets, which is especially relevant for non-ASCII source.

For `tokenize.generate_tokens()` and simple line-based strings, one possible conversion is:

```python
code = 'x = 1\nprint(x)\n'
starts = [0]
for line in code.splitlines(keepends=True):
    starts.append(starts[-1] + len(line))

# For a token with start == (line_no, column):
line_no, column = (2, 0)
character_offset = starts[line_no - 1] + column
print(character_offset)  # 6
```

Do not directly add an AST node's `col_offset` to character-based line starts when non-ASCII characters may appear earlier in the same line. For your first chunker, full-line boundaries from `lineno` and `end_lineno` are much simpler and safer.

## 5. Common traps

- A literal string such as `"# not a comment"` is a string token, not a comment.
- An unclosed bracket/string or malformed source may raise `tokenize.TokenError`; other malformed input may behave differently.
- The tokenizer does not decide which comments logically belong to which definition; your chunker needs that policy.
- Don't assume every token's `.string` corresponds to a normal non-empty slice of the source file.

## 6. A possible chunking workflow

1. Parse Python with `ast` to locate top-level functions and classes.
2. Map their whole-line start/end positions into character offsets.
3. Optionally inspect tokens or preceding lines to attach useful leading comments.
4. Split oversized units along meaningful boundaries, with a fixed-size fallback.
5. Verify every `chunk.text == original[first:last]` and the configured max size.

There is **no requirement** in the 42 subject to use `tokenize`. It is one tool you might choose when refining retrieval quality.
