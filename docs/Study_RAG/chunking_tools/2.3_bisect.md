## 1. The problem

A `MinimalSource` uses character indices, but while debugging you may want to know the line containing a particular character. Scanning every line works, but repeated lookups can benefit from binary search.

## 2. Build a line-start table

```python
code = 'abc\ndef\nxyz'
line_starts = [0]
for line in code.splitlines(keepends=True):
    line_starts.append(line_starts[-1] + len(line))
print(line_starts)  # [0, 4, 8, 11]
```

The last value `11` is the **exclusive end** of the file. The real lines start at indices `0`, `4`, and `8`.

| Position | Character | Line (1-based) |
|---:|:---:|---:|
| 0 | `a` | 1 |
| 3 | `\n` | 1 |
| 4 | `d` | 2 |
| 8 | `x` | 3 |
| 10 | `z` | 3 |

## 3. `bisect_right()`

```python
from bisect import bisect_right

line_starts = [0, 4, 8, 11]
position = 5
insertion_point = bisect_right(line_starts, position)
print(insertion_point)  # 2
```

`bisect_right(sorted_values, x)` gives the insertion index **after** any values equal to `x`. Therefore, `bisect_right(line_starts, position) - 1` gives the zero-based line index, for any position representing a character in the text.

## 4. Convert a character position into a line number

```python
from bisect import bisect_right

text = 'abc\ndef\nxyz'
line_starts = [0, 4, 8, len(text)]

position = 8
assert 0 <= position < len(text)
line_number = bisect_right(line_starts, position)
print(line_number)  # 3 (1-based)
```

The line number is 3 because `position = 8` is the first character of line 3.

**Boundary rule:** `position == len(text)` is **not** a character. It represents the exclusive end. Handle it separately instead of treating it as belonging to another line. For an empty file, no character position is valid.

## 5. `bisect_left()` versus `bisect_right()`

```python
from bisect import bisect_left, bisect_right
starts = [0, 4, 8, 11]
print(bisect_left(starts, 4))   # 1
print(bisect_right(starts, 4))  # 2
```

On an exact boundary, the two functions differ. `bisect_right()` is convenient because the boundary at `4` belongs to the line **starting** at `4`.

## 6. When (not) to use it

- **Useful:** map found matches or errors from character offsets back to source line numbers.
- **Not necessary:** convert an AST `node.lineno` to characters. You already know the line number; simply index `line_starts[node.lineno - 1]`.
- **Performance:** `bisect` is O(log n) per lookup in a sorted list, versus linear scanning; creating the line-start table itself still takes time proportional to the file size.
